# Structured work records, templates and revision acknowledgement

Architectural additive update to the published Rapport AI. Human authorized autonomous routine design; source audit precedes implementation. Product checkout is isolated; root exclusively runs every compiler/test/device/sign/store workload. No production implementation before root observed RED.

## Intent and novelty
Keep entered work, materials and measurements reliable alongside an AI-worded narrative, then reuse empty work structures and retain exactly what was saved or acknowledged. Existing source has customer/site/system/trade/tone, speech/raw text, editable generated narrative, local saved reports, company profile, A4 PDF with stable report number and blank paper signature lines. It has no structured line-item model, user templates, customer acknowledgement record or immutable per-report revisions. The UI tab called history is the latest report list, not revision history. SpeechTranscriber uses “revision” for recognition corrections; Billing uses acknowledgement for store purchases. Neither provides these business features.

Selected approach: extend the existing local report domain and native editors with an explicit revision snapshot on successful save. Alternative separate unlinked worksheets would lose the connection between work entries and report content; replacing the whole app/report model would risk speech, subscriptions and old data. The additive domain with compatible persistence is recommended.

## Domain decisions
- Work item kinds: labor, material, measurement. Stable ID and nonblank description. Labor uses entered integer minutes (no inferred time). Other entries use entered nonnegative decimal quantity with at most3 fractional digits and a nonblank unit. Group quantities only for the same kind+exact normalized unit; no implicit unit conversion or currency/invoice totals. At most1000 lines per report, each labor duration at most1000000 minutes; decimal quantity at most999999999.999. No negative/nonfinite/overflow or silent rounding.
- Reusable named trade template copies kind/description/unit only, with blank quantities/durations. Applying a template creates fresh IDs and never imports another customer's names, work quantities, measurements, acknowledgement or history. Users explicitly fill facts. No example values treated as completed work.
- Immutable revision content includes all current report context, raw narrative, edited report narrative, tone/trade and work items. Explicit successful save appends an independently copied numbered snapshot only when content changed; repeated unchanged save is a no-op revision. First save of an existing legacy report preserves the loaded legacy content as revision1 before adding an actual change as revision2. Stable report ID/createdAt/report number remain intact.
- Acknowledgement is an explicitly entered name and confirmation note bound to a selected saved revision ID/time. It is a local record of confirmation, not a digital signature, authenticated identity, trusted timestamp, legal acceptance or tamper-proof audit. Later revisions keep earlier acknowledgement attached to its earlier snapshot and show that latest content is not acknowledged. Never transfer it to a new revision automatically.

## Persistence and integrations
Extend RapportDraft/Rapport with compatible default decoding for new optional fields and explicit schema handling. Preserve existing Swift reports.json ISO8601 arrays and Android reports_v1 records exactly on migration, with stable IDs/dates/report text. New Foundation/JVM-testable archive codecs validate all fields/IDs/revision relationships, distinguish missing first install from corrupt/future data and reject malformed/trailing JSON. Disk failure saves nothing visible; publish after durable success. Never silently replace unreadable existing data. Android minSdk24 prevents unconditional use of API26 java.nio atomic moves: use platform AtomicFile adapter or a safe API24-compatible replacement strategy with rollback and tests.

Keep current monthly/annual products and5 free AI generations/month, profile/logo/speech and backend generation request unchanged. New local workflow is free; no new paid gate. Typed measurements/material quantities are user-entered and stay out of the unchanged network request. AI never fills those fields or changes acknowledged snapshots.

Native SwiftUI/Compose editors use text-backed validation, stacked fields and saveable drafts. Report create/detail both expose the workflow, templates and revision selection. Historical revisions are read-only, with inspection, sharing and explicit revision-bound acknowledgement. No restore action is included in this release. All new UI and report additions have DE/EN strings. Existing German-only strings are not claimed already localized.

PDF/export append actual structured inputs with units and revision/acknowledgement labels to the existing paginated body, preserving narrative, company profile/logo and report number. Do not turn blank paper signature lines into a claimed electronic signature. Root verifies actual long PDF pages, Unicode, final acknowledgement area and exact visible values; source-only PDF/layout success is not sufficient.

## Acceptance and boundaries
Deterministic decimal and minute totals; unlike units never summed; invalid visible input cannot save stale values; template fresh IDs/blank facts; snapshots independent; duplicate save no extra revision; acknowledgement stays with old revision after edit; legacy dates/IDs/text retained; corrupt/future/trailing/malformed archives and save failures preserve original bytes. Native speech deny/offline, draft rotation/Duo transition, long DE/EN and large text, PDF actual page output/share and Pro quota regressions remain root acceptance. No version bumps/push/store changes by worker. No live-binary source confirmation inferred from identity/main pin.
