## Novelty and chosen approach
Existing source already contains23 manual jobs (one active),8 locations, pooled employee hiring/passive income, contracts, quality/reviews, streak/events, daily goals/achievements, prestige, major projects, offline income, ads/IAP, responsive shell. Do not market those as new. New: assign staff to up to3 concurrent small team service orders, choose specialization and pace, inspect deterministic quoted time/quality/bonus, collect completed bonuses individually. This adds planning decisions to passive staff without replacing the existing manual job loop.

Three approaches considered: upgrade existing single-job loop to multiple manual jobs (would alter cooldown/event/streak rules), create fully individual employee identities (large save/economy migration), or add a bounded team board using existing hired employee counts. Choose the third. Passive staff/contract earnings remain exactly as before, including staff currently dispatched; explain this explicitly in UI. Team orders are an additional bounded bonus channel and do not grant manual-job XP/reputation/reviews/streak/goal credit or ad multipliers.

## Exact rules
- Staff types azubi/monteur/meisterin retain old counts/income. Saved specialization per staff type: sanitaer/heizung/planung; defaults match existing trades. At most3 live team orders; one hired unit backs one order until collection. Same order archetype cannot be active twice. Each assignment snapshots type/specialization/pace and quote, so later preference edits never change a running task.
- Orders: armaturen (Sanitärkontrolle, sanitaer, level1,120sec,35EUR base); heizcheck (Heizungscheck, heizung, level3,240sec,75EUR); planung (Material- und Terminplanung, planung, level5,360sec,100EUR). These are explicitly small team orders, separate from manual jobs.
- Quality=72+experience(azubi0/monteur4/meisterin8)+8 for matching specialization+pace delta(schnell-12/normal0/sorgfalt+8), clamped50..100. Duration=max1, base seconds*pace multiplier(0.75/1/1.4). Reward cents=round(base EUR*quality); shown before assignment and immutable thereafter. No RNG or inferred real-world workmanship claim.
- Counts, identifiers, numbers and saved records strictly validated. Unknown/invalid/future new board data blocks writes while original save remains untouched. Legacy saves without board get empty board/default profiles. Monotonic task IDs; at most5 recent completion records.
- Process elapsed time only once; nonnegative finite time, cap each offline advancement at8hours; completion waits for explicit collect and never starts another job automatically. Repeated collection returns nothing. Save state includes board and balance together; on failed assignment/profile/collection persistence restore in-memory state and display error. Atomic same-directory save replacement after successful temp write; no deletion of last good original before replacement. Prestige/location reset clears operational board and its profiles alongside existing operational staff reset; no outstanding tasks silently lost: block reset/prestige while a team task remains.
